## 名单日期

详情页将选择日以 `date=YYYYMMDD` 传给名单接口。冻结详情脚本中 `minDate` 使用 `subtract(8, "days")`，`maxDate` 为当天；这是向前偏移 8 个自然日的含两端区间（跨度 8 天，最多含 9 个自然日期，页面另禁选周末），不是“最近 8 个交易日”，也不等于后台承诺保留多少天。代码以响应 `qdate` 为锚，采用 `0 <= qdate - requested_day <= 8` 的保守边界；已有合成边界测试覆盖偏移 8 天允许、9 天拒绝。联网对照中，2026-10-28、2026-10-29 的名单内容分别随选择日变化，`qdate` 却仍为 2026-10-30；不能再用 `qdate != requested_day` 判定历史名单错日。

输出同时保留：

| 字段 | 含义 |
| --- | --- |
| `requested_day` | 调用方请求日 |
| `day` | 采用的名单日；核验不足时为空 |
| `date_basis=portal_date_parameter` | 日期依据为门户的 `date` 请求参数契约，**不是响应日期回显** |
| `date_basis=response_date` | 响应额外提供合法、与请求日一致的 `data.date` |
| `date_basis=unverified` | 无有效日期依据 |
| `date_basis=synthetic_demo` | 仅演示接口：日期及名单均为程序合成，不标真实完整名单 |
| `upstream_qdate` | 上游原始 `qdate` 的公历解析值；不改写成历史名单日期，不猜它的更精确业务含义 |

请求日晚于 `qdate`、相对 `qdate` 超出 8 个自然日、日期非法，或显式 `data.date` 不符：拒绝采用名单。缺少两个日期字段时可保留行供排查，但 `day=None`、`list_complete=False` 且有缺口。没有伪造服务端对每条记录的日期证明，也不宣称支持长期历史。

仅有匹配的 `data.date` 时，日期仍可标记为 `response_date`，但没有 `qdate` 就无法核验近期窗口：保留行及明确缺口，`list_complete=False`，不宣称该日期的完整名单，也不把空列表标为完整空池。不会借用本机今天让历史冻结响应随重放时间改变结论。

所有名单返回路径（含默认离线、坏编码/JSON、拉取失败、合成演示）都包含上表的日期字段、`list_complete` 和 `latest_price_unit`。无法解析的失败路径默认 `list_complete=False`、`date_basis=unverified`、`upstream_qdate=None`，同时保留合法请求日和缺口；不会要求调用方靠 `.get()` 绕过漏字段。演示用 `date_basis=synthetic_demo`，保持只读、合成且 `list_complete=False`。

`list_complete` 只表示采用日期依据及近期窗口核验成立、`tc` 为非负整数且与原始及去重后行数一致、未触及页大小上限。它不表示所有可选字段均已给出；字段错误仍在 `gaps` 中。`data=null`、缺 `pool`、缺 `tc`、计数不符或损坏行均不能当作完整空池。非法调用参数仍抛 `ValueError`，不伪装为一次已执行的查询。

## 跌停池与价格

门户配置中涨停、炸板默认排序为 `fbt:asc`，跌停为 `fund:asc`。单变量联网对照复现：给跌停池错误的 `fbt:asc` 会出现总数非零、名单为空；改为 `fund:asc` 后恢复，且与总数一致。代码按池类型使用各自排序，不自动改试其他端点。

跌停的连续天数读取 `days`，开板次数优先读取 `oc`，最后封板时间读取 `lbt`。兼容旧合成输入的 `ocnt`；存在非法 `oc` 时不拿旧字段掩盖错误。

门户价格显示函数明确将 `p` 除以 1000，再显示两位小数；三个同期样本的换算值与新浪报价一致。因此 `latest_price=p/1000`、`latest_price_unit=CNY`。整数与浮点使用相同尺度；无效值留空，不补零。新浪仅用于此次独立核对，没有加入程序的数据源或依赖。

## 分布的 23 个桶与汇总范围

门户图例明确列出 `-11` 到 `11`：

| 桶 | 门户含义 |
| --- | --- |
| `-11` | 跌停 |
| `-10` | 低于 -9%，且未跌停 |
| `-9` … `-1` | -9% 至 -8% … -1% 至 0% |
| `0` | 平盘 |
| `1` … `9` | 0% 至 1% … 8% 至 9% |
| `10` | 高于 9%，且未涨停 |
| `11` | 涨停 |

涨跌停与相邻的极端未封板桶互斥，不能再额外加一次涨跌停数。区间端点的精确归属沿用上游分桶，不在本地根据涨跌幅重新分配。

每个方向全部 11 个有效桶齐全时才计算 `up` / `down`；`0` 桶有效时才能给出 `flat`。三个方向都已知且快照日期合法时才给出 `sample`。缺日期/坏日期时，即使桶齐全也令 `sample=None`、`complete=False`；有效桶、图例和方向小计可保留供审阅，不能绑定观察日。缺失不补零；重复同值去重，冲突不覆盖、不相加；图例外字段使统计范围未知，暂停汇总。只有全桶齐全且快照日期合法时 `complete=True`。

合成演示的分布同样遵守无日期规则：`day=None` 时返回 `sample=None`、`complete=False`，即使调用方传入日期也不会把它填成快照日。三个示例的分桶及说明保留，并明确标记 `synthetic=True`；示例家数不充当完整样本总数。

`aggregation_scope=eastmoney_portal_distribution` 仅表示这份门户分布的合计。未取得其完整证券纳入/排除规则，不把它命名为全部 A 股家数，不要求它与不同来源、不同时间的涨跌停名单家数相等，不与同花顺七组分布拼接。分布接口没有历史日参数，仍只认响应当天快照。
